## Summary

Implemented the stub-producer side of `next-issue` plus three new producer-suite
scenarios (all uncommitted, on branch `agent/issue-15`):

- `stub-producer/agentctl`: durable one-shot `next issue N` priority end to end.
  `_fresh_state`/`_load_state` carry `priority`; `_status` renders it via new
  `_priority_status` (`{request_id, issue}`); `_mutation_payload` maps
  `next-issue` to `("next_issue", {"issue": N})`; new `_do_next_issue` rejects
  explicitly-ineligible issues with `rejected` (nothing stored, ID reusable),
  supersedes the previous priority, commits `accepted`, and saves
  `priority` durably; `_maybe_open_claim` consumes the priority at the Claim
  boundary (unknown/absent entry = eligible, claims it and marks `completed`;
  explicitly-ineligible entry = `not_fulfilled` via new `_resolve_priority`
  and normal selection proceeds); claim body extracted into `_open_claim` so
  both paths share the after-claim crash handling. `_do_mutation` and the
  bottom fallback route `next-issue` (error message updated to "stop, resume
  and next issue only"). Smoke-tested directly: commit/claim/completed,
  ineligible-at-commit rejected + `not_found` + ID reusable for stop,
  ineligible-at-claim `not_fulfilled` with fallback claim of another issue,
  supersession (first `superseded`, second claims). Fixed `_open_claim`'s
  `armed` annotation to plain `Any`.
- `stub-producer/harness`: `_FRESH_DOC` now includes `"priority":null` so fresh
  volumes match the stub state shape.
- `src/agent_operator_contract/producer_suite.py`: new `_CAPABILITY_PROBES`
  table (pool excluded, it declares no operation); rewrote
  `scenario_unsupported_capability` to probe every capability missing from
  `ctx.capabilities` (checks exit 3 + `details.capability`, `command` is
  `not_found`, request ID reusable for `stop` with intake steering between
  probes); added `scenario_stop_after_invalid` (`--after 0` is
  `invalid_argument`, nothing stored, ID reusable), `scenario_stop_after_restart`
  (plan `stop --after 2`: counted 1/2 stays `accepted` with intake open, restart
  via stop/start-container preserves `{remaining 2, counted 1}`, second

  `scenario_next_issue_restart` (held `next issue 122` survives restart and
  claims 122 with `completed`; then held `next issue 124` made ineligible
